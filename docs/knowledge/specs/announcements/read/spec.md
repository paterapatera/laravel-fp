# お知らせの閲覧

## Purpose
ログイン済みの利用者が公開対象のお知らせを一覧と詳細で読めるようにする。

## Scope
公開対象の判定、一覧、詳細、空の一覧、見つからない詳細。認証の入口は [ダッシュボードへのアクセス](/specs/dashboard/access/) に属する。管理画面での作成と編集は範囲外である。

## Definitions
公開対象は、次をすべて満たすお知らせである。状態が published である。タイトル、要約、本文のそれぞれに空白以外の文字がある。公開の開始と終了の両方がある。アプリケーションの現在時刻が開始以上かつ終了以下である。開始の瞬間と終了の瞬間は含む。空白だけとは、文字が無いか、空白文字だけであることをいう。

一覧上限は、ダッシュボードの一覧に出す公開対象の件数として受け付ける整数である。その範囲は0以上10以下であり、0件と10件は範囲に入り、11件は範囲の外である。測定は NFR-ANN-1 である。

省略の知らせは、続きがあること、全件数、または残件数を示すことである。

## Identifier
Code: ANN

## Requirements

### REQ-ANN-1: List title and summary
- Process: ダッシュボードのお知らせ一覧 (EQ)

ログイン済みの利用者がダッシュボードを開いたとき、システムは一覧に含める公開対象のタイトルと要約を示さなければならない。

#### Scenario: Visible announcement
- **前提** ログイン済みの利用者と、公開対象のお知らせが一件ある
- **もし** ダッシュボードを開く
- **ならば** そのタイトルと要約が一覧に出る

#### Scenario: Draft is excluded
- **前提** ログイン済みの利用者と、期間内だが draft のお知らせがある
- **もし** ダッシュボードを開く
- **ならば** そのタイトルは一覧に出ない

#### Scenario: Outside the window is excluded
- **前提** ログイン済みの利用者と、published だが現在時刻が終了より後のお知らせがある
- **もし** ダッシュボードを開く
- **ならば** そのタイトルは一覧に出ない

#### Scenario: Inclusive start
- **前提** ログイン済みの利用者と、現在時刻が開始の瞬間と等しい公開対象がある
- **もし** ダッシュボードを開く
- **ならば** そのタイトルが一覧に出る

#### Scenario: Inclusive end
- **前提** ログイン済みの利用者と、現在時刻が終了の瞬間と等しい公開対象がある
- **もし** ダッシュボードを開く
- **ならば** そのタイトルが一覧に出る

#### Scenario: Missing end is excluded
- **前提** ログイン済みの利用者と、published で本文が揃っているが終了が空のお知らせがある
- **もし** ダッシュボードを開く
- **ならば** そのタイトルは一覧に出ない

#### Scenario: Blank summary is excluded
- **前提** ログイン済みの利用者と、要約が空白だけのお知らせがある
- **もし** ダッシュボードを開く
- **ならば** そのタイトルは一覧に出ない

#### Scenario: Blank title is excluded
- **前提** ログイン済みの利用者と、タイトルが空白だけのお知らせがある
- **もし** ダッシュボードを開く
- **ならば** その要約は一覧に出ない

### REQ-ANN-2: Same list for every user
ログイン済みの利用者がダッシュボードを開いたとき、システムは他のログイン済み利用者と同じ公開対象を示さなければならない。

#### Scenario: Two users
- **前提** 二人のログイン済み利用者と、公開対象が二件ある
- **もし** それぞれがダッシュボードを開く
- **ならば** 二人の一覧に同じ二件のタイトルが出る

### REQ-ANN-3: Hide the body on the list
ログイン済みの利用者がダッシュボードを開いたとき、システムは公開対象の本文を出さないままにしなければならない。

#### Scenario: Body stays off the list
- **前提** ログイン済みの利用者と、本文が要約にもタイトルにも含まれない公開対象がある
- **もし** ダッシュボードを開く
- **ならば** その本文は一覧に出ない

### REQ-ANN-4: Sort the list
公開対象が複数ある間、システムは公開開始の新しい順に、開始が同じなら作成の新しい順に、それも同じなら文字符号点の昇順にタイトルを並べなければならない。

#### Scenario: Newer start comes first
- **前提** ログイン済みの利用者と、開始が異なる公開対象が二件ある
- **もし** ダッシュボードを開く
- **ならば** 開始が新しい方が先に出る

#### Scenario: Newer creation breaks a start tie
- **前提** ログイン済みの利用者と、開始が同じで作成時刻が異なる公開対象が二件ある
- **もし** ダッシュボードを開く
- **ならば** 作成が新しい方が先に出る

#### Scenario: Title breaks the remaining tie
- **前提** ログイン済みの利用者と、開始と作成時刻が同じでタイトルの文字符号点が異なる公開対象が二件ある
- **もし** ダッシュボードを開く
- **ならば** 文字符号点が小さいタイトルが先に出る

### REQ-ANN-5: Empty list
公開対象が無い間、システムはお知らせが無いことをダッシュボードに示さなければならない。

#### Scenario: Nothing stored
- **前提** ログイン済みの利用者と、お知らせが一件も無い
- **もし** ダッシュボードを開く
- **ならば** お知らせが無いことが示される
- **かつ** 一覧に項目は無い

#### Scenario: Only hidden announcements
- **前提** ログイン済みの利用者と、draft のお知らせだけがある
- **もし** ダッシュボードを開く
- **ならば** お知らせが無いことが示される

### REQ-ANN-6: Show title and body
ログイン済みの利用者が公開対象の詳細を開いたとき、システムはそのタイトルと本文を示さなければならない。

#### Scenario: Open a visible announcement
- **前提** ログイン済みの利用者と、公開対象が二件ある
- **もし** そのうち一件の詳細を開く
- **ならば** その一件のタイトルと本文が出る
- **かつ** もう一件の本文は出ない

### REQ-ANN-7: Hide the summary on the detail
ログイン済みの利用者が公開対象の詳細を開いたとき、システムは要約を出さないままにしなければならない。

#### Scenario: Summary stays off the detail
- **前提** ログイン済みの利用者と、要約がタイトルにも本文にも含まれない公開対象がある
- **もし** その詳細を開く
- **ならば** その要約は詳細に出ない

### REQ-ANN-8: Unreadable detail
ログイン済みの利用者が公開対象でない詳細を開いたとき、システムは本文の無い見つからない結果を示さなければならない。

#### Scenario: Missing announcement
- **前提** ログイン済みの利用者と、該当するお知らせが無い
- **もし** 詳細を開く
- **ならば** 見つからない結果が出る
- **かつ** 本文は出ない

#### Scenario: Draft detail
- **前提** ログイン済みの利用者と、draft のお知らせがある
- **もし** その詳細を開く
- **ならば** 見つからない結果が出る
- **かつ** 本文は出ない

#### Scenario: Before the start
- **前提** ログイン済みの利用者と、現在時刻が開始より前の published のお知らせがある
- **もし** その詳細を開く
- **ならば** 見つからない結果が出る
- **かつ** 本文は出ない

#### Scenario: After the end
- **前提** ログイン済みの利用者と、現在時刻が終了より後の published のお知らせがある
- **もし** その詳細を開く
- **ならば** 見つからない結果が出る
- **かつ** 本文は出ない

#### Scenario: Blank body
- **前提** ログイン済みの利用者と、本文が空白だけの published のお知らせがある
- **もし** その詳細を開く
- **ならば** 見つからない結果が出る

#### Scenario: Missing start
- **前提** ログイン済みの利用者と、開始が空の published のお知らせがある
- **もし** その詳細を開く
- **ならば** 見つからない結果が出る
- **かつ** 本文は出ない

### REQ-ANN-9: Open the chosen announcement
ログイン済みの利用者が一覧のお知らせを選んだとき、システムはそのお知らせの詳細を示さなければならない。

#### Scenario: Choose the second item
- **前提** ログイン済みの利用者と、一覧に並ぶ公開対象が二件ある
- **もし** 二件目を選ぶ
- **ならば** 二件目の詳細が出る

### REQ-ANN-10: No editing controls
一覧または詳細を示すとき、システムはお知らせの編集と削除の操作を出さないままにしなければならない。

#### Scenario: List has no editing controls

- **前提** ログイン済みの利用者と、公開対象がある
- **もし** ダッシュボードを開く
- **ならば** 編集と削除の操作は無い

#### Scenario: Detail has no editing controls

- **前提** ログイン済みの利用者と、公開対象がある
- **もし** その詳細を開く
- **ならば** 編集と削除の操作は無い

### REQ-ANN-11: Reject announcement changes
お知らせの変更または削除を求められた場合、システムは保存済みのタイトル、要約、本文を維持しなければならない。

#### Scenario: Submitted change
- **前提** ログイン済みの利用者と、保存済みの公開対象がある
- **もし** そのタイトルの変更を求める
- **ならば** 保存済みのタイトル、要約、本文は変わらない

### REQ-ANN-12: Show the prefix of the current order
- Process: ダッシュボードのお知らせ一覧 (EQ)

ログイン済みの利用者がダッシュボードを開いたとき、システムは公開対象を REQ-ANN-4 の順の先頭から一覧上限まで示さなければならない。

#### Scenario: Direct dashboard URL
- **前提** ログイン済みの利用者と、開始がすべて異なり、一覧上限より多い公開対象がある
- **もし** `/dashboard` を開く
- **ならば** 開始が新しい方から一覧上限までのタイトルが出る

#### Scenario: Welcome link
- **前提** ログイン済みの利用者と、開始がすべて異なり、一覧上限より多い公開対象がある
- **もし** ウェルカムのダッシュボードへのリンクを開く
- **ならば** 開始が新しい方から一覧上限までのタイトルが出る

#### Scenario: Login shows the dashboard
- **前提** 用意された利用者と、保護画面を求める前のログインと、開始がすべて異なり、一覧上限より多い公開対象がある
- **もし** 一致する認証情報でログインする
- **ならば** 開始が新しい方から一覧上限までのタイトルが出る

#### Scenario: Retry after a mismatch
- **前提** 用意された利用者と、ログイン失敗の上限内の不一致と、開始がすべて異なり、一覧上限より多い公開対象がある
- **もし** 続けて一致する認証情報でログインする
- **ならば** 開始が新しい方から一覧上限までのタイトルが出る

#### Scenario: Authenticated user opens login
- **前提** ログイン済みの利用者と、開始がすべて異なり、一覧上限より多い公開対象がある
- **もし** ログインを開く
- **ならば** 開始が新しい方から一覧上限までのタイトルが出る

#### Scenario: Fewer than the limit
- **前提** ログイン済みの利用者と、一覧上限より少ない公開対象がある
- **もし** ダッシュボードを開く
- **ならば** すべてのタイトルが REQ-ANN-4 の順に出る

#### Scenario: Count equals the limit
- **前提** ログイン済みの利用者と、一覧上限と同数の公開対象がある
- **もし** ダッシュボードを開く
- **ならば** すべてのタイトルが REQ-ANN-4 の順に出る

#### Scenario: Drafts do not take a slot
- **前提** ログイン済みの利用者と、一覧上限より多い下書きと、一覧上限より少ない公開対象がある
- **もし** ダッシュボードを開く
- **ならば** 公開対象のすべてのタイトルが出る

#### Scenario: Newer creation stays in the prefix
- **前提** ログイン済みの利用者と、開始が同じで作成時刻が異なり、一覧上限より多い公開対象がある
- **もし** ダッシュボードを開く
- **ならば** 作成が新しい方から一覧上限までのタイトルが出る

#### Scenario: Title order stays in the prefix
- **前提** ログイン済みの利用者と、開始と作成時刻が同じでタイトルの文字符号点が異なり、一覧上限より多い公開対象がある
- **もし** ダッシュボードを開く
- **ならば** 文字符号点が小さい方から一覧上限までのタイトルが出る

#### Scenario: Equal order keeps the limit
- **前提** ログイン済みの利用者と、開始と作成時刻とタイトルが同じで、一覧上限より多い公開対象がある
- **もし** ダッシュボードを開く
- **ならば** 一覧の項目数は一覧上限と同じである

#### Scenario: Admin sees the same prefix
- **前提** 管理者と、管理者でないログイン済みの利用者と、開始がすべて異なり、一覧上限より多い公開対象がある
- **もし** それぞれがダッシュボードを開く
- **ならば** 二人に、開始が新しい方から一覧上限までの同じタイトルが出る
