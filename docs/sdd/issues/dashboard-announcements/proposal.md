# ログイン後のダッシュボードでお知らせを見られるようにする

## Why

ログイン済みの利用者がアプリに入った直後に、運用側からの重要な告知を逃さず確認できるようにする。お知らせ本文を一覧にすべて載せず、要約と詳細を分けることで、ダッシュボードの可読性を保ちつつ必要な情報へ辿れるようにする。

## What Changes

- **認証とダッシュボード**: 未認証ユーザーはログイン／登録（方式は設計で決定）を経て、認証済みユーザーだけがアクセスできるダッシュボード画面を用意する。現状存在しない `/dashboard` 相当のルートと画面を本変更で整える。
- **お知らせの永続化**: お知らせをデータベースに保存するモデルとマイグレーションを追加する。開発・テスト用の Factory / Seeder でサンプルデータを用意する。
- **一覧表示**: ダッシュボード上に、公開対象のお知らせをシンプルな一覧として表示する。各項目はタイトルと短い要約（または本文の抜粋）程度に留める。
- **詳細表示**: 一覧から個別のお知らせの全文を読める詳細画面（または同等の画面遷移）を提供する。一覧と詳細の両方は認証済みユーザーのみが利用できる。
- **公開データの投入**: 管理 UI は別 issue とするため、初期リリースでは Seeder・Artisan、または運用手順で定めた方法により DB にお知らせレコードを投入する前提とする。公開期間・下書きなどの細かい運用ルールは要件フェーズで具体化する。

## Impact

- **Type**: feat
- **Capabilities**:
  - New `/specs/dashboard/` — 認証済みユーザー向けダッシュボードへのアクセスと画面の振る舞い
  - New `/specs/announcements/` — お知らせの一覧・詳細表示（利用者向け読み取り）
- **Steering**: none
- **Decisions**: none（認証スタックの選定などは設計フェーズで ADR 化を検討）
- **Code**: `routes/web.php`、認証まわり（`app/Http/`、設定）、`app/Models/`、マイグレーション、Blade ビュー、Feature テスト、Seeder / Factory

## Out of Scope

- お知らせの作成・編集・削除を行う管理画面や API（別 issue）
- 未ログインユーザー向けのお知らせ表示や公開トップページへの埋め込み
- メール・プッシュなどの通知配信
- お知らせへのコメント、既読管理、お気に入り
- リッチテキストエディタやメディア添付の本格対応（プレーンテキストまたは最小限の HTML 表示に留めるかは設計で決定）
- 多言語切り替えやテナント別お知らせ
